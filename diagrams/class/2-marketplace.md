# 类图 2：商品、收藏、购买请求与订单

对应图：[2.jpeg](2.jpeg)。

## 设计主体思路

以 `SecondhandItem` 为交易对象，围绕“用户发布商品 → 买家提出购买请求 → 达成订单 → 约定交接地点”组织业务。分类、标签和收藏服务于浏览与检索，不与实际交易记录混为一体。

## 对应的用户用例

| 用例 | 类图覆盖内容 |
| --- | --- |
| `UC-2201` 浏览和筛选商品 | `SecondhandItem`、`ItemCategory` 和 `ItemTag` 支持商品信息及分类、标签检索；校园归属由类图 1 的 `Campus` 和 `User` 补充。 |
| `UC-2202` 收藏商品 | `SavedItem` 记录用户收藏商品及收藏时间。 |
| `UC-2401` 提出购买请求 | `PurchaseRequest` 表示针对具体商品的出价、留言和处理状态；一件商品可对应多个请求。 |
| `UC-3201` 发布二手商品 | `SecondhandItem`、`ItemCategory` 和 `ItemTag` 表达商品挂牌资料、分类及标签；发布操作本身不在类图中规定。 |
| `UC-3202` 管理自己发布的商品 | `SecondhandItem` 记录发布者和商品状态；状态变更及停止接受请求的规则属于业务约束。 |
| `UC-3401` 处理购买请求 | `PurchaseRequest` 与 `TransactionOrder` 表达请求处理及由请求形成订单的关系；商品占用和其他请求拒绝规则需由业务逻辑落实。 |
| `UC-3402` 保存常用交接地点 | `PickupPoint` 表达订单交接地点；图中未表示地点归属卖家，因此个人常用地点的归属关系尚未覆盖。 |
| `UC-3403` 确认订单完成 | `TransactionOrder` 的状态可记录订单完成；由卖家确认以及线下交易的边界需由业务规则落实。 |
| `UC-4401` 达成订单和交接安排 | `TransactionOrder`、`PurchaseRequest`、`User` 和 `PickupPoint` 表达请求、交易双方、约定价格与交接地点之间的关系。 |
| `UC-4402` 跟进线下交易 | `TransactionOrder` 支持记录订单状态及交接安排；线下付款由双方自行完成，不由类图或平台处理。 |
| `UC-4403` 取消订单 | `TransactionOrder` 状态承载取消结果；解除商品占用、重新开放请求及不恢复已拒绝请求的规则需由业务逻辑落实。 |
| `UC-5201` 维护商品分类与标签 | `ItemCategory` 和 `ItemTag` 表达供商品描述和检索使用的分类、标签；管理员维护操作不在类图中规定。 |
| `UC-5601` 查看平台运营概况 | 商品和订单数据可作为统计来源；运营指标、统计口径及汇总视图未在类图中建模。 |

## 包含的实体

| 实体 | 作用 |
| --- | --- |
| `User` | 商品发布者、购买请求提交者、订单买家或卖家，以及收藏者。 |
| `SecondhandItem` | 保存商品标题、描述、标价、状态、图片、品牌、型号、成色等挂牌信息。 |
| `ItemCategory` | 商品分类，包含名称、说明、启用状态及子分类结构。 |
| `ItemTag` | 可复用的商品标签。 |
| `SavedItem` | 用户与商品之间带有收藏时间的关联记录。 |
| `PurchaseRequest` | 针对某件商品提出的报价、留言、时间和处理状态。 |
| `TransactionOrder` | 记录达成交易后的约定价格、日期、交接时间及订单状态。 |
| `PickupPoint` | 记录交接地点的名称、地址、坐标和启用状态。 |

## 主要关系

- 一名 `User` 可发布 0 到多件 `SecondhandItem`；每件商品由 1 名用户发布，并归入 1 个 `ItemCategory`。一个分类可包含 0 到多件商品。
- `ItemCategory` 可有 0 到多个子分类；每个子分类最多有 1 个父分类。`SecondhandItem` 与 `ItemTag` 为多对多关系。
- `SavedItem` 连接 1 名用户和 1 件商品；用户与商品各自都可对应 0 到多条收藏记录。
- 一名用户可提交 0 到多个 `PurchaseRequest`；每条请求指向 1 件商品，一件商品可收到 0 到多条请求。
- 每笔 `TransactionOrder` 来自 1 条购买请求，使用 1 个 `PickupPoint`，并分别关联 1 名买家和 1 名卖家；一条购买请求最多产生 1 笔订单。地点和用户可分别关联多笔订单。

## 特殊考量

- `SavedItem` 是带 `dateSaved` 的关联类，不能仅以商品上的收藏计数替代；同一用户对同一商品的重复收藏应在实现中避免。
- `ItemCategory` 的父子关系与商品标签承担不同用途：前者形成分类层级，后者允许一件商品拥有多个检索标记。
- 请求中的 `offeredPrice`、商品的 `askingPrice` 与订单中的 `agreedPrice` 分别表示出价、标价和成交价，不能相互覆盖。
- 图中订单与商品通过购买请求间接关联；创建订单时应核实请求、买家、卖家及商品状态一致，并避免一件不可再次出售的商品被重复成交。
